## Summary

`v0.8.0` is a scale, diagnostics, inventory-correctness, and provenance release. It makes the full extract → weave → generate sequence viable at the measured 1,700-term nested-source workload, replaces broad planner-shape failures with condition-specific operator guidance, repairs MeshInventory history-page drift, and aligns integration/extraction digest evidence with SFLO `v0.4.0`.

This is a minor release because it adds an untargeted batching capability, introduces a consumer-visible finding code, changes diagnostic text, changes generated RDF placement for `integrate`, and intentionally rejects legacy repository-locator digest data. It is not a `v0.7.1` patch.

## Highlights

- **Extracted-term batching removes the quadratic planner path.** A homogeneous untargeted set of `firstExtractedKnopWeave` candidates now plans as one coherent `VersionPlan`, in canonical order, with one shared MeshInventory advancement. Mixed, recursive, overwrite, later-payload, single-target, and explicit multi-target routing retain their existing paths.
- **ResourcePage generation is render → write → discard.** Page models are visited canonically, decoded raw-source contents are shared by absolute path for the command, and at most four rendered pages are retained per batch. Created/updated/skipped path ordering and generated bytes remain stable.
- **Measured scale headroom is restored.** On the faithful current-only nested `catalog/source` workload at N=1,700, composed weave fell from 3.79 GiB to 802 MiB peak RSS and same-timestamp standalone generate fell from 3.74 GiB to 674 MiB. The N=500→1,700 curves are sublinear, and same-timestamp regeneration changes no pages or non-HTML bytes.
- **Planner failures name the failed condition.** Thirty-seven malformed or incoherent-state assertions now identify the designator, file, RDF subject, missing/conflicting fact, and correction instead of reporting a “settled slice shape” implementation detail.
- **SFLO `v0.4.0` digest provenance.** Standing byte claims, caller expectations, and computed observations are kept on their distinct RDF subjects; exact source bytes and typed observation timestamps are preserved.
- **SFLO Pages dogfooding closes two carried-inventory gaps.** Next-state intent remains valid when a canonical `sfcfg:` prefix was appended late, and versioning preserves all repeated source-registry/reference-catalog subject blocks.

## Breaking Or Changed Behavior

- **Eligibility: untargeted all-extracted first-payload sets batch.** A command that previously entered the per-candidate sequential loop now succeeds as one coherent batch when every selected candidate is `firstExtractedKnopWeave`. The working MeshInventory advances once for the set, not once per candidate. Mixed and recursive sets remain sequential.
- **Resource use: generation concurrency is bounded at four rendered pages.** This is an internal fixed bound, not a new setting. The report surface remains path-only; rendered contents are no longer retained for the whole corpus.
- **Instrumentation: memory reports gained page-generation and live-set fields.** With `WEAVE_MEMORY_STATS`, reports include rendered page/batch counts, maximum batch files/bytes, deduplicated candidate/source retention, planning iterations, and maximum RSS. The estimator counts shared text and byte identities once and computes UTF-8 sizes without transient encoded buffers.
- **Diagnostics: broad planner error strings changed.** True-invariant and malformed-state failures now use condition-specific messages. Consumers must not match the removed prose. Acceptance predicates were not widened by the diagnostic conversion.
- **Finding codes: `malformed-knop-metadata` is new.** Invalid KnopMetadata Turtle, missing `rdf:type sflo:Knop`, missing `hasWorkingKnopInventoryFile`, and missing `designatorPath` use this consumer-visible finding code instead of `unsupported-mesh-shape`.
- **MeshInventory history pages are correct at the version boundary.** Batch and sequential version operations regenerate `_mesh/_inventory/<history>/index.html` from actual progressed RDF, including named and gapped states. Previously the page could remain stale until a later `generate`; generated HTML bytes change for affected meshes.
- **Repository locators no longer carry digest claims.** `RepositorySourceLocator` and `RepositorySourceFloatingLocator` output contains none of `hasContentDigest`, `expectsContentDigest`, or `observedContentDigest`.
- **Computed integration digests are observations.** A digest computed from bytes read by `integrate` is written as `observedContentDigest` on an `ArtifactResolutionObservation`, never copied into `expectsContentDigest`. Only a caller-supplied `--source-digest` becomes an expectation.
- **Repository-backed observations identify the file read.** Their `observedArtifactResolutionSpec` includes the concrete local relative path resolved by the runtime instead of an empty coordinate node.
- **Expected digest input is exact.** `--source-digest` and programmatic expected-digest inputs accept only `sha256:` plus 64 lowercase hexadecimal digits. Uppercase, abbreviated, non-hexadecimal, missing-prefix, and unsupported-algorithm values are rejected rather than normalized.
- **Legacy locator digests fail closed with migration guidance.** Active source-registry parsing rejects repository locator `hasContentDigest` and names both valid destinations: `expectsContentDigest` on the resolution spec for a pre-existing requirement, or `observedContentDigest` on an observation for computed evidence.
- **Extraction hashes exact bytes.** Extract computes SHA-256 from the source `Uint8Array` before UTF-8 decoding, so BOM and other byte-level differences are not erased by decode/re-encode.
- **Observation timestamps are typed.** Core extract, runtime extract, and extraction-source renderers emit `observedAt` as `xsd:dateTime`; invalid lexical values are rejected.
- **Valid `LocatedFile` standing claims remain supported.** `hasContentDigest` on a legitimate SFLO digest bearer is accepted and preserved.
- **Payload next-state intent normalizes canonical prefix placement.** If an append-shaped inventory declares `@prefix sfcfg:` after the subject receiving `hasNextStateSegmentHint`, Weave moves the canonical declaration before use and emits valid Turtle.
- **Repeated support subject blocks are preserved.** When an append-shaped KnopInventory carries one source registry or reference catalog across multiple same-subject blocks, versioning retains all immutable type, working-file, and opaque facts rather than only the first block.
- The ANSI-only version-output test cleanup changes no release behavior.

## Upgrade From v0.6.0

Consumers moving directly from `0.6.0` inherit all `v0.7.0` changes as well as this release. Review [[release-notes.v0.7.0]] in full. In particular:

- untargeted multiple first-payload candidates batch into one MeshInventory advancement;
- nested extraction sources no longer require synthesized ancestor Knops;
- current-only ReferenceCatalog inventory updates are append/no-op/conflict planned and may have different but semantically equivalent Turtle bytes;
- inventory conflict detection is stricter, and vocabulary-namespace IRIs with path separators no longer compact to invalid prefixed names;
- `@semantic-flow/weave-lib` is ESM-only; CommonJS `require()` remains unsupported.

Before pinning `0.8.0`, migrate any active source registry that places `hasContentDigest` on a repository locator. Put a deliberately supplied requirement on the owning `ArtifactResolutionSpec` as `expectsContentDigest`; put computed historical evidence on an `ArtifactResolutionObservation` as `observedContentDigest`. Use only canonical lowercase SHA-256 values. The active parser reports this migration directly and does not provide a pre-1.0 compatibility shim.

Stagecraft and other consumers that inspect `integrate` output must update expectations: the repository locator has no digest property, the computed digest is on the linked observation, an expectation exists only when the caller supplied one, and repository-backed observed coordinates include the concrete local path read.

## Known Limitations

- Weave remains pre-1.0 and intentionally ships no compatibility parser for legacy repository-locator digests.
- SHA-256 is the only supported expected/observed digest method; directory trees and abstract RDF graphs have no canonical digest contract.
- Failed-resolution provenance is not modeled by the successful observation path. A digest mismatch fails before successful use or persistence.
- The scale acceptance substrate is the faithful current-only N=1,700 workload. Larger corpora and different history policies were not part of the closure bound.
- Some planner gates remain fixture-shaped implementation debt even though the malformed-state diagnostic families shipped here are condition-specific; do not infer general support for mixed or recursive batching.
